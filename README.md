# 数据产品运营与归因分析平台

面向数据产品运营、渠道归因、用户行为分析、ROI评估、转化优化与数据应用监控的数据分析工程平台。

这是一个**纯前端**管理平台：React + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 React + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/local-service.ts   本地数据服务：列表、筛选、动作流转、导出
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

## 基准映射（竞品对标 → 留存方案）

「基准映射」页（导航：基准映射，路由 `/benchmark-mapping`）把对标方案的对比指标转换成可核查的
留存阈值，解决指标只能人工判断差距的问题。领域逻辑集中在
`frontend/src/api/mapping-service.ts`，映射数据独立持久化在 localStorage 键
`data-product-ops:benchmark-mappings`：

- 为每个对标方案选择**对比指标、基准值、适用初始事件**，同时生成留存方案的**候选阈值**
  （基准值 − 4 个百分点安全垫）与**预计留存差距**，对标结论同时引用基准值与留存结果。
- 三要素任一不可核查（指标不匹配、基准值非数值、初始事件不属于留存方案）即**映射失败**，
  对标方案与留存方案都不会进入启用状态，失败记录写明异常原因并支持修正后重试。
- 启用映射前必须先**确认主对标**：同一人群（同一留存方案）多个对标方案时，只有明确指定的
  主对标可启用；主对标关系变更只把旧主对标转为「待复核」，不直接改写已启用方案。
- 启用瞬间**固定对标版本快照**（版本号、锁定基准值、来源、时间），并把候选阈值回写留存方案；
  之后竞品基准变化只计算漂移，漂移超过 **4 个百分点**差值容限才转「待复核」，由人工选择
  采纳新基准或维持原版本。
- 页面内置故障演练开关与「中断恢复」区：生成中断会落恢复任务（含异常原因），可重试或放弃；
  无映射数据时展示空态。

验收样例已播种为 BMAP-0001：BENC-0002（次月留存率 42%，monthly，来源 R-2026-11）映射
RETE-0002（初始事件：付费下单），生成 38% 候选阈值与 4 个百分点预计差距，主对标未确认前
不能启用。规则校验脚本：

```bash
cd frontend
npm run verify:mapping
```

## 约定

- 每个模块的页面在 `frontend/src/views/<模块>/index.vue`，页面只负责渲染，读写统一走
  `frontend/src/api/local-service.ts`。
- 字段、状态、动作与流转目标集中在 `frontend/src/data/modules.ts`；示例数据在
  `frontend/src/data/seed.ts`。
- 状态流转只允许在 `local-service.ts` 里改，页面组件不做业务判断。
- 想回到初始数据：清掉浏览器里 `data-product-ops:entries` 这一项，或调用 `resetModule(模块)`。
